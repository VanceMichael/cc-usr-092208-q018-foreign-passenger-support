# 外籍旅客身份服务接续

帮助外籍铁路旅客在购票、进站和退改渠道间安全接续身份服务。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例（当前为 v2，样本编号 record-018）。参与方包括外籍铁路旅客、车站服务人员、铁路客服中心、隐私合规人员。

资料所依据的领域事实如下：

- 铁路部门适应过境免签带来的客流增长
- 全国铁路发送外籍旅客同比显著增长
- 铁路部门为外籍旅客出行提供便利
- 外籍旅客在线上客服与车站窗口之间转换时需要重复解释证件信息
- 工作人员手工合并旅客档案曾造成他人车票被错误退改

## v2 领域规则

v2 在 v1 基础资料之上，把以下规则写成可校验的结构：

- **跨渠道接续（continuity）**：线上客服转车站窗口时，在本人同意下接续证件版本、核验结果、购票身份、行程关联、多语种求助、人工处置六类资料，旅客无需重复解释护照姓名顺序、拉丁字符转写或证件换发经过，并可跨渠道延续同一请求。
- **同意范围（consent）**：授权由旅客本人持有、可撤回；六类接续资料逐一说明用途；与本次出行无关的签证资料明确禁止复制，撤回后停止接续并记入审计。
- **审慎消歧（disambiguation）**：姓名近似、同行家庭、跨境行程、离线窗口补录四类场景必须采用审慎规则并保留人工确认；匹配置信度低于门槛（示例 0.95）一律转人工，禁止自动合并。
- **最小必要（privacy）**：车站窗口只看到当前处置所需信息；证件换发后仅展示新版本与必要对照摘要；接续资料设保留期限并到期清理；车站可见范围不得包含已排除资料。
- **审计回溯（audit）**：必须能够发现错误合并、越权查阅、超期保留三类风险，并支持从退改结果反向查回真实授权与核验过程。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、约束，以及 v2 的接续前提、同意边界、审慎消歧、最小可见与审计回溯规则（v1 资料仍保持可读）。测试还会构造违规变体，确认以下情形被拒绝：无同意接续、授权复制无关签证资料、低置信度不转人工、撤回后无最小可见说明、车站可见已排除资料、审计无法发现错误合并或无法从退改结果回溯授权等。
